# 蜀道安全助手 — 前端设计文档

> 文档定位：为「蜀道安全助手」Web 端提供唯一、可落地的视觉与交互规范。
> 适用角色：管理员、安全员、普通员工三类。
> 生成日期：2026-08-16

## 1. 设计概述

### 1.1 产品背景

蜀道安全助手是面向工程建设、安全生产场景的一体化管理系统，核心包含隐患安全管理、AI 智能助手、考试工坊三大业务模块，并包含用户管理、消息通知、个人中心等基础能力。

### 1.2 设计理念

整体采用**工作台（Workspace）形态**：任务导向、左右分区，强调「进入一个模块即进入一个工作场景」，而非传统后台的菜单点开表格。

- **秩序**：左侧导航 + 历史记录，中间主体，右侧按需辅助面板，结构一致。
- **警示**：隐患等级、风险状态用语义色一眼可辨。
- **克制**：弱化装饰，服务高频、重复的安全生产操作。

### 1.3 设计范围

登录注册、工作台首页、隐患管理、AI 智能助手、考试工坊、消息通知中心、个人中心、系统用户管理。

## 2. 技术栈

| 层级 | 选型 | 说明 |
| --- | --- | --- |
| 框架 | Vue 3 + TypeScript + Vite | 与 PRD、ARCHITECTURE 一致 |
| UI 组件库 | Element Plus（定制主题） | 通过设计令牌覆盖为本文档风格 |
| 样式 | CSS 变量 + SCSS 主题覆盖 | 设计令牌映射到 Element Plus 变量 |
| 状态管理 | Pinia | 用户态、权限、通知未读等全局状态 |
| 路由 | Vue Router 4 | 路由级权限守卫 |
| HTTP | Axios | 拦截器统一鉴权、刷新、错误码处理 |
| 图表 | ECharts | 统计看板、趋势图 |
| 流式输出 | fetch + ReadableStream | `/ai/chat` 为 POST SSE，EventSource 不支持 POST，故用 fetch 流式读取 |

> 组件库统一为 **Element Plus**（与 PRD / ARCHITECTURE 一致），不再采用 Arco。

## 4. 整体布局（工作台）

### 4.1 全局框架

- 顶部：56px 顶栏，左侧系统 Logo + 「蜀道安全助手」，右侧消息通知（未读角标）、个人中心、退出登录。
- 左侧：固定侧边栏，分上下两区：
  - **上区（模块导航）**：隐患管理、AI 智能问答、考试工坊、消息通知、个人中心；（管理员额外）用户管理。
  - **下区（当前模块历史记录）**：展示当前模块的历史条目，顶部固定「新建任务」按钮。
- 主内容区：当前模块的工作台主体。
- 右侧辅助面板（按需）：隐患「分析报告」、考试「实时预览」等。

### 4.2 工作台通用结构

每个业务模块遵循「左历史 / 中主体 / 右面板」：

```
┌──────────┬──────────────────────────┬─────────────┐
│ 模块导航  │                          │             │
│ 历史记录  │      模块主体内容         │  右侧辅助面板 │
│ +新建任务 │                          │  (按需)     │
└──────────┴──────────────────────────┴─────────────┘
```

### 4.3 响应式

- 桌面端优先，适配 1920 / 1440 / 1280 分辨率。
- 宽度 < 1280 时收起右侧辅助面板；< 1024 时历史记录侧栏转为抽屉。
- 表格、图片区支持横向滚动，不允许溢出。

## 5. 各模块界面

### 5.1 隐患管理（工作台）

- **左侧**：历史记录列表（隐患上报记录）。
- **中间主体**：隐患图片区。
  - 未上传时显示空态占位：「请上传图片（最多 9 张）」。
  - 上传后显示经 AI 识别、OpenCV 标注后的隐患图片，标注框按风险等级着色（高红 / 中橙 / 低绿）。
- **右侧「分析报告」面板**：展示图片中识别出的隐患信息（隐患名称、风险等级、位置说明、整改建议、置信度等），按风险高→中→低排序，与标注图联动。
- 上报落地：分析报告下方提供「补全信息并上报」入口，填写 PRD H01 要求的标题、描述、位置、等级、类别、时间后提交。

### 5.2 AI 智能问答

- **左侧**：历史会话列表，顶部「新建任务」按钮。
- **中间主体**：仿豆包对话区，底部固定输入栏。
  - 流式逐字输出、停止生成、点赞/踩。
- **引用规范展示**：回答下方按规范类别分组，多行显示：
  - 例如：「国家规范 …… XX 条」「地方规范 …… XX 条」。
  - 每行右侧带下箭头，点击展开显示具体规范名称；点击规范名称跳转到对应网页（依赖后端 `source_uri`）。
- **原文引用标注**：回答正文中被引用的内容用**黑体**标注。

### 5.3 考试工坊（管理员 / 安全员）

- **左侧**：历史记录（试卷 / 出题记录），顶部「新建任务」。
- **中间主体**：出卷工作台，自上而下：
  - 「试卷名称」标题（粗体）。
  - 「出题依据内容」输入框，占位文字（淡灰色）「请输入章节、知识点或培训内容……」。
  - 「从附件生成考题」上传组件：支持 xlsx，最多 5 个附件，**直接解析附件内题目、不经过 AI**。
  - 「题型设置」板块（粗体）+「附带出题依据条款」可选项框。
  - 题型数量配置：单选、判断、多选、简答，各一个数量输入框。
- **右侧「实时预览」面板**：实时显示当前试卷名称、题型及每类数量。

### 5.4 考试工坊（普通员工）

- **左侧**：历史记录（我的考试）。
- **中间主体**：仅展示「是否收到考试」；若收到则显示考试链接。
  - 点击链接直接进入考试页面（无需填写个人信息）。
- **考试页交互**：
  - 单选 / 多选：选项框。
  - 判断：显示「对」「错」两个选项框。
  - 简答：输入框，最多 2000 字。
  - 支持题目标记、切屏提示、自动保存。

### 5.5 其它模块

- **工作台首页**：数据概览卡片（隐患总数、闭环率、待办、已考人数）、隐患趋势图、快捷入口、最新动态。
- **消息通知**：分类标签页 + 列表 + 单条/批量已读删除。
- **个人中心**：个人信息、修改密码。
- **用户管理（管理员）**：用户列表 + CRUD + 角色分配。

## 6. 核心组件规范

### 6.1 按钮

| 类型 | 样式 | 用途 |
| --- | --- | --- |
| 主按钮 | Primary 背景、白字 | 核心操作 |
| 次按钮 | 白底、1px 边框 | 次级操作 |
| 幽灵按钮 | 透明、主色字 | 行内轻量操作 |
| 危险按钮 | Danger | 删除、驳回 |

高度 32px（默认）/ 36px（大号），内边距 8px 16px，文字 14px，带图标优先。

### 6.2 等级 / 状态标签

浅底 + 深字，圆角 4px，字号 12px。隐患等级四色 + 流程状态（待处理蓝 / 处理中橙 / 待验收黄 / 已闭环绿 / 已驳回红）。

### 6.3 表格

表头浅灰底、固定表头；行高 48px；斑马纹与 hover；高等级隐患行左侧 3px 色条；操作列固定右侧；空态 / 加载态统一组件。

### 6.4 表单

输入框高度 32px，聚焦主色 2px 边框，错误态红边 + 精确文案；必填红星号；前置校验并聚焦第一个错误框。

### 6.5 卡片与统计

卡片白底、1px 边框、8px 圆角、16px 内边距；统计卡「数值 + 标签 + 趋势副标题」。

### 6.6 弹窗与抽屉

二次确认用弹窗；隐患详情 / 时间线用右侧抽屉（宽 640px）；遮罩 `rgba(16,24,40,0.45)`。

### 6.7 消息与通知

未读角标红色圆点，超 99 显示 `99+`；分类遵循 PRD「隐患类 / 考试类」+「全部 / 未读 / 已读」；高危催办置顶。

## 7. 交互与动效

- 动效统一 200ms，仅用于 hover、展开、弹窗淡入、流式光标。
- 异步操作（提交、导出、AI 生成、上传、解析）必须 Loading。
- 破坏性操作用弹窗二次确认；结果用轻提示。
- AI 流式输出逐字平滑；支持停止生成。
- 高危隐患不闪烁，用左侧色条 + 加粗强调，避免视觉噪音。

## 8. 认证与权限（前端侧）

- Token：refresh 持久化，access 常驻内存；Axios 拦截器自动附加 `Authorization: Bearer`。
- `40103` 触发 refresh 轮换并重试；`40100`（30 分钟空闲）清理会话跳转登录。
- 空闲：前端 30 分钟无操作定时器 + 后端 `40100` 兜底。
- 权限：路由守卫按角色拦截；按钮级 `v-permission` 指令控制显隐。

## 9. 与后端能力的一致性说明

| 前端设计 | 后端实现 | 状态 |
| --- | --- | --- |
| 从附件生成考题（xlsx，直接解析，不经过 AI） | `POST /exam/questions/import?enter_bank=false`，返回 `question_ids`；不进入题库的题目 `source=paper_attachment`，题库列表自动过滤 | 已实现（后端） |
| 题型：单选 / 判断 / 多选 / 简答 | `single_choice / true_false / multi_choice / essay` | 一致 |
| 「附带出题依据条款」复选框 | `AiGenerateRequest.include_basis`，勾选后在生成提示词中要求把依据条款写入 `explanation` | 已实现 |
| 引用规范分类「国家 / 地方规范」+ 跳转网页 | RAG 检索结果新增 `standard_level`，由 `jurisdiction` 推导（国家→国家规范、集团/公司/企业→企业规范、其余→地方规范）；`source_uri` 供跳转 | 已实现 |
| 简答 2000 字限制 | `save_answer` 对 essay 类型校验 `ESSAY_MAX_LENGTH=2000` | 已实现 |
| 员工免填个人信息直接考试 | `my-exams` + `paper_assignees` 已识别用户 | 一致，无需个人信息步骤 |

> 前端待办：考试工坊「从附件生成考题」的可移动弹窗（拖拽 + 「是否进入题库」选择）为前端交互组件，后端已就绪，实现页面时补齐即可。
