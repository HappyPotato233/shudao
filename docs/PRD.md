## 1. 产品概述与背景说明

### 1.1 项目背景

蜀道集团作为大型交通建设企业，业务涵盖高速公路、铁路、港口等交通基础设施建设与运营，安全生产管理是其核心业务之一。当前安全生产管理面临以下挑战：

- **隐患管理效率低**：隐患上报依赖纸质表单或微信群通知，信息流转慢、易遗漏，难以追踪闭环状态。
- **安全知识获取难**：一线员工遇到安全问题时缺乏即时、权威的解答渠道，依赖经验判断，风险高。
- **安全培训考核成本高**：传统线下培训考试组织周期长、覆盖面有限，难以满足全员安全教育的常态化需求。
- **数据沉淀不足**：安全隐患数据分散，缺乏系统化统计分析手段，无法支撑管理层的科学决策。

基于上述痛点，蜀道集团决定通过 AI 技术赋能传统安全管理流程，打造集**隐患排查、智能问答、考试工坊**于一体的智能化安全管理平台——「蜀道安全助手」。

### 1.2 产品定位

「蜀道安全助手」是一款面向蜀道集团全体员工的 AI 驱动安全生产管理平台，通过三大核心模块构建安全生产管理的数字化闭环：

| 模块      | 核心能力                      | 价值主张            |
| ------- | ------------------------- | --------------- |
| 隐患安全管理  | 隐患全生命周期管理（上报→派单→整改→验收→闭环） | 隐患闭环率提升，响应时效缩短  |
| AI 智能助手 | 基于企业安全知识库的多轮智能问答          | 安全知识即时可达，降低咨询成本 |
| 考试工坊    | 题目数量选择、试卷名称设置、试卷预览、发送、出题历史记录 | 出题自动化，覆盖面扩大   |

### 1.3 核心目标

1. **隐患闭环率 ≥ 95%**：通过系统化流转与消息通知机制，确保隐患从上报到闭环全程可追踪。
2. **安全知识即时响应**：AI 问答首字响应 ≤ 3 秒，基于企业安全知识库精准回答，消除幻觉。
3. **培训考核全覆盖**：支持全员安全培训考核，AI 出题降低命题成本 80% 以上。
4. **高并发支撑**：系统支持 ≥ 200 并发用户，AI 问答支持 ≥ 50 QPS。

### 1.4 技术栈

| 层级    | 技术选型                                         |
| ----- | -------------------------------------------- |
| 前端    | Vue 3 + TypeScript + Element Plus            |
| 后端    | FastAPI + SQLAlchemy                         |

| 部署    | Docker + Nginx                               |

### 1.5 名词解释

| 术语   | 说明                                                 |
| ---- | -------------------------------------------------- |
| 隐患   | 可能导致安全事故的不安全状态、不安全行为或管理缺陷                          |
| 闭环   | 隐患从发现到完成整改验收的全过程结束状态                               |

## 2. 用户角色定义

### 2.1 角色概述

本系统定义两类用户角色，覆盖安全生产管理的各层级参与者：

#### 2.1.1 管理员（Admin）

- **定位**：后台管理者与模型测试决策者，通常为信息中心管理员或安全管理部门负责人。
- **职责**：AI 模型配置、RAG 内容配置、知识库维护、AI 模型测试与切换评估、系统用户管理。
- **特征**：仅具备配置、管理、测试能力，无任何隐患管理与考试业务操作权限，与用户端完全隔离。

#### 2.1.2 普通用户（User）

- **定位**：一线操作人员与安全管理人员，涵盖施工人员、技术人员等全体员工。
- **职责**：隐患识别与上报、隐患派单、整改反馈、AI 安全问答咨询、考试工坊（出题/组卷/预览/发送）。
- **特征**：所有普通用户功能完全一致、无任何差别，均无后台配置、用户管理、模型管理权限。

## 3. 功能需求描述

### 3.1 隐患安全管理模块

#### H01 — 隐患上报

**用户故事：**

> 作为一名普通用户，我希望能够通过手机快速上报发现的安全隐患，包括拍照、描述隐患信息并选择隐患等级，以便安全管理人员及时获知并处理。

**功能描述：**

- 支持填写隐患标题、详细描述、发生位置（支持地图选点）、发生时间。
- 支持现场拍照上传（最多 9 张）。
- 需选择隐患等级：重大隐患、较大隐患、一般隐患、轻微隐患。
- 需选择隐患类别：如高处作业、临边防护、机械伤害、消防安全、临时用电等。
- 可选择隐患所属项目/标段。
- 上报后自动生成隐患编号，状态为「待处理」。

**验收标准：**

1. 上报页面首屏加载时间 ≤ 2 秒。
2. 单张照片不支持压缩，单张最大 20MB，上传成功率 ≥ 99%。
3. 必填字段未填写时，提交按钮置灰并给出提示。
4. 上报成功后，生成唯一隐患编号（格式：HD-YYYYMMDD-XXXX），并跳转至隐患详情页。
5. 上报成功后，隐患进入「待处理」状态，等待上报人派单；派单后系统自动向被指派人推送消息通知（见 H08）。

---

#### H02 — 隐患列表

**用户故事：**

> 作为一名普通用户，我希望能够查看管辖范围内的所有隐患列表，并按状态、等级、时间进行筛选和排序，以便快速掌握隐患整体情况。

**功能描述：**

- 列表展示字段：隐患编号、标题、等级（带颜色标签）、状态、上报人、上报时间、所属项目。
- 支持多维度筛选：隐患等级、状态流转、隐患类别、时间范围、所属项目。
- 支持关键字搜索（标题、编号、描述）。
- 支持按上报时间、紧急程度排序。
- 分页展示，每页默认 20 条，支持切换 10/20/50 条。
- 列表项点击跳转至隐患详情（H03）。
- 普通用户仅可见本人上报的隐患。

**验收标准：**

1. 列表数据加载时间 ≤ 500ms（接口响应）。
2. 筛选条件切换后，列表 1 秒内刷新。
3. 不同角色看到的数据范围符合权限矩阵定义。
4. 隐患等级以颜色标签区分：重大（红色）、较大（橙色）、一般（黄色）、轻微（蓝色）。
5. 空数据时展示友好空状态提示。

---

#### H03 — 隐患详情

**用户故事：**

> 作为一名普通用户，我希望能够查看某条隐患的完整信息，包括上报内容、图片、处理过程记录和当前状态，以便全面了解隐患情况并做出处理决策。

**功能描述：**

- 展示隐患基本信息：编号、标题、描述、等级、类别、位置、上报时间、上报人。
- 展示现场图片，支持点击放大查看（图片支持手势缩放）。
- 展示隐患状态流转时间线：每个状态节点的操作人、操作时间、备注。
- 展示处理记录：派单信息、整改反馈、验收结果。
- 根据当前状态和用户角色，动态展示操作按钮：
  - 待处理 + 上报人（普通用户）→ 显示「派单」按钮。
  - 待验收 + 上报人（普通用户）→ 显示「验收」按钮。
  - 已驳回 + 被指派人 → 显示「重新整改」按钮。
- 支持导出隐患详情单（PDF 格式）。

**验收标准：**

1. 详情页加载时间 ≤ 1 秒。
2. 图片预览支持左右滑动浏览、双指缩放。
3. 状态流转时间线完整展示所有历史节点，不可篡改。
4. 操作按钮的显示/隐藏严格遵循角色权限与当前状态。
5. PDF 导出内容完整、格式规范，生成时间 ≤ 5 秒。

---

#### H04 — 隐患派单

**用户故事：**

> 作为一名普通用户，我希望能够将待处理的隐患指派给具体的责任人，并设置整改期限和整改要求，以便推动隐患及时整改。

**功能描述：**

- 选择整改责任人（支持按部门/项目筛选人员）。
- 填写整改要求（必填）。
- 设置整改截止日期（必填，不早于当前日期）。
- 可上传附件（整改指导文件等，最多 5 个文件）。
- 可设置优先级：紧急、高、中、低。
- 派单后隐患状态从「待处理」变更为「处理中」。
- 系统自动向被指派人推送消息通知（见 H08）。
- 若整改期限临近未反馈，系统自动发送催办通知。

**验收标准：**

1. 派单操作完成后，状态立即变更为「处理中」，时间线新增派单节点。
2. 被指派人收到消息通知的延迟 ≤ 5 秒。
3. 整改截止日期到达前 24 小时未收到反馈时，自动发送催办通知。
4. 重大隐患派单时，强制要求填写整改要求且整改期限 ≤ 7 天。
5. 派单信息不可重复提交（防抖处理）。

---

#### H05 — 整改反馈

**用户故事：**

> 作为一名被指派整改的用户，我希望能够提交整改完成情况，包括整改措施说明和整改后照片，以便上报人进行验收。

**功能描述：**

- 填写整改措施描述（必填，不少于 20 字）。
- 上传整改后照片（必填，至少 1 张，最多 9 张）。
- 可上传整改相关附件（如维修单据等）。
- 填写整改完成时间（默认当前时间）。
- 提交后隐患状态从「处理中」变更为「待验收」。
- 系统自动向派单人推送消息通知。
- 若整改被驳回，状态变为「已驳回」，可重新提交整改反馈。

**验收标准：**

1. 提交整改反馈后，状态立即变更为「待验收」。
2. 整改后照片与上报照片支持对比查看（左右分屏/滑动对比）。
3. 整改措施描述少于 20 字时，提交按钮置灰并提示。
4. 驳回后重新提交时，保留驳回原因展示，并记录新一轮整改信息。
5. 消息通知延迟 ≤ 5 秒。

---

#### H06 — 隐患验收

**用户故事：**

> 作为一名普通用户，我希望能够对整改完成的隐患进行验收，查看整改前后对比并给出验收结论，以便闭环隐患或驳回重新整改。

**功能描述：**

- 展示隐患原始信息和整改反馈信息。
- 支持整改前后照片对比查看。
- 填写验收结论：通过 / 驳回（二选一）。
- 填写验收意见（通过时选填，驳回时必填，不少于 10 字）。
- 可上传验收附件（现场复核照片等）。
- 验收通过：状态变为「已闭环」，隐患流程结束。
- 验收驳回：状态变为「已驳回」，触发整改人重新整改。
- 验收结果记录在状态流转时间线中。

**验收标准：**

1. 验收通过后状态变更为「已闭环」，不可再操作。
2. 验收驳回时必须填写驳回原因，否则无法提交。
3. 驳回后系统自动通知整改责任人，延迟 ≤ 5 秒。
4. 已闭环的隐患在列表中显示绿色闭环标识。
5. 验收操作记录（操作人、时间、结论、意见）完整写入时间线。

---

#### H08 — 消息通知

**用户故事：**

> 作为一名普通用户，我希望能够及时收到隐患相关的消息通知（如被派单、整改被驳回、验收结果等），以便第一时间响应处理。

**功能描述：**

- **通知类型**：
  - 隐患被派单（通知整改责任人）。
  - 整改反馈已提交（通知派单人）。
  - 验收通过/驳回（通知整改责任人）。
  - 整改催办（临近截止日期提醒）。
  - 系统通知（system_message，管理员向指定用户推送）。
- **通知渠道**：站内消息（铃铛图标红点提示）+ 邮件通知 + SSE 实时推送。
- **消息分类**：支持按分类 tab 展示（隐患类）。隐患类含派单、整改反馈、验收结果、整改催办。支持按类型（4 类）筛选。
- **消息列表**：默认展示全部消息，未读消息置顶，按时间倒序排列；支持按「全部 / 未读 / 已读」切换筛选；未读消息高亮；支持单条标记已读、全部标记已读。
- **消息详情**：支持查看单条消息详情，并可跳转至对应业务详情页。
- **消息删除**：支持单条删除与批量删除，删除后不再展示。
- **未读角标**：红点显示未读总数，并支持按分类（隐患类）展示分类型未读计数。
- 支持消息推送偏好设置（可开关各类通知）。

**验收标准：**

1. 消息推送延迟 ≤ 5 秒（从事件触发到消息到达），SSE 实时推送连接稳定。
2. 未读消息数量实时更新，红点角标准确，支持按分类（隐患类）展示分类型未读计数。
3. 点击消息可查看消息详情并正确跳转至对应隐患详情页。
4. 消息列表支持分页加载（每页 20 条），默认未读置顶，支持按分类 / 类型 / 已读状态筛选。

#### H09 — AI 隐患智能识别（隐患上报增强）

**用户故事：**

> 作为一名普通用户，我希望上传现场照片后系统能自动识别潜在隐患并给出标注结果，以便快速补全隐患信息、提高上报效率。

**功能描述：**

- **需求概述**：用户仅需上传现场照片，系统调用大模型识别潜在隐患并返回结构化 JSON，后端 CV 服务在「复制出的原图副本」上按检测结果绘制标注框，返回标注图给前端展示，辅助用户快速补全隐患信息。
- **输入要求**：现场照片必填（最多 9 张，单张 ≤ 20MB，不压缩）；隐患标题选填；图片描述选填。
- **后端处理流程**：
  1. 前端上传图片，后端保存原图；
  2. 后端调用大模型视觉识别接口，输入原图，返回检测结果 JSON；
  3. 后端调用 CV 服务：复制一份原图（原图保持不变），在副本上按每条结果的 `bbox_norm` 换算像素坐标、按 `color_bgr` 绘制矩形框并在框上方绘制文字标签，生成标注图并保存；
  4. 后端返回「原图 URL + 标注图 URL + 检测结果 JSON」给前端。
- **检测结果 JSON 字段定义**：

  | 字段 | 类型 | 说明 |
  | --- | --- | --- |
  | `id` | int | 检测项序号 |
  | `label` | string | 隐患名称/类别 |
  | `risk` | string | 风险等级：高（high）/ 中（medium）/ 低（low） |
  | `bbox_norm` | float[4] | 归一化边界框 `[x1, y1, x2, y2]`，取值 0~1 |
  | `bbox_px` | float[4] \| null | 像素坐标边界框，可选，默认 null |
  | `color_bgr` | int[3] | 标注框颜色，BGR 顺序（OpenCV 格式） |
  | `conf` | float | 置信度 0~1 |
  | `fix` | string | 整改建议 |
  | `note` | string | 隐患位置/说明备注 |

  示例（低风险项颜色为绿色 `[0, 255, 0]`）：

  ```json
  {
    "detections": [
      {
        "id": 1,
        "label": "临边防护缺失",
        "risk": "high",
        "bbox_norm": [0.10, 0.22, 0.62, 0.78],
        "bbox_px": [120, 264, 744, 936],
        "color_bgr": [0, 0, 255],
        "conf": 0.92,
        "fix": "立即设置临时防护，安装正式护栏",
        "note": "3号桥墩东侧临边"
      },
      {
        "id": 2,
        "label": "安全帽未佩戴",
        "risk": "low",
        "bbox_norm": [0.30, 0.40, 0.55, 0.70],
        "bbox_px": [360, 480, 660, 840],
        "color_bgr": [0, 255, 0],
        "conf": 0.88,
        "fix": "要求现场人员正确佩戴安全帽",
        "note": "作业区西侧人员"
      }
    ]
  }
  ```

- **风险等级与颜色映射（BGR）**：
  - 高 = 红色 = `[0, 0, 255]`
  - 中 = 橙色 = `[0, 165, 255]`
  - 低 = 绿色 = `[0, 255, 0]`
- **标签文字**：仅显示 `label`，风险等级通过颜色体现（不附加 risk 文字）。
- **原图与标注图**：两者均保存，H03 隐患详情中都可查看。
- **前端展示**：标注图与检测清单联动展示；清单按 risk 高→中→低排序，逐条展示 label/risk/conf/fix/note。
- **异常边界**：
  - 无隐患检出（空数组）时提示「未识别到明显隐患」，但仍可手动填写上报；
  - 识别接口异常时降级为普通图片上传，不阻塞上报；
  - 多图时每张独立识别，返回各自 JSON 与标注图。
- **与 H01 的衔接**：H01 隐患上报上传图片后自动触发本能力，识别结果辅助用户确认/修正后提交，提交后进入原有待处理流转。

**验收标准：**

1. 上传现场照片后，系统在合理时间内返回检测结果 JSON 与标注图。
2. 标注框按 `bbox_norm` 准确定位，颜色与风险等级映射一致（高红/中橙/低绿），文字仅显示 `label`。
3. 原图保持原样，标注图在副本上生成，两者均可保存并在 H03 详情查看。
4. 检测清单按风险高→中→低排序，逐条展示 label/risk/conf/fix/note。
5. 无隐患检出时提示「未识别到明显隐患」且不阻塞手动上报；识别接口异常时降级为普通上传，不影响上报。
6. 多图上传时每张图片独立识别，各自返回 JSON 与标注图。

#### A05 — 知识检索

**用户故事：**

**功能描述：**

- 采用 RAG（检索增强生成）技术：用户提问 → 双集合向量检索 + BM25 关键字检索 → RRF 融合 → 检索结果 + 用户问题 → 大模型生成回答。
- 知识库双集合并存：内置法规证据链集合（safety_evidence_v1，只读）+ 管理端上传知识库集合（safety_knowledge），检索时两路向量召回合并融合，结果标注来源集合。
- 知识库来源：安全生产法律法规、企业安全操作规程、事故案例库、应急预案等。
- 知识库管理（管理员）：支持文档上传（PDF/Word/TXT/Markdown，≤50MB）、自动解析、按语义段落自动分块（分块大小/重叠等参数由管理端 RAG 配置统一调整）、向量化入库；文档状态流转 parsing → chunking → indexing → indexed / failed，支持查询解析状态；删除文档时同步清理向量、分块记录与文件。
- 检索结果展示：回答中标注引用的知识来源（见 A06）。
- 支持知识库分类管理（管理员）：分类树增删改查，按法规类、规程类、案例类等分类。
- 普通用户仅可查询/检索知识库内容，无知识库管理与审核权限。

**验收标准：**

1. 知识检索耗时 ≤ 1 秒（不影响首字响应 ≤ 3 秒的总目标）。
2. 检索 Top-K（K=5）相关文档片段参与回答生成。
3. 文档上传后 5 分钟内完成解析和向量化入库。
4. 知识库支持 ≥ 10000 篇文档，检索准确率 ≥ 85%。
5. 知识库内容更新后，新回答能引用到最新内容。

**性能保障措施：**

- **前端**：路由懒加载、组件按需加载、图片懒加载与压缩、CDN 静态资源加速、Redis 缓存热点数据。

- **AI**：流式输出减少用户等待感、向量检索异步预处理、大模型 API 请求队列与限流。
- **数据库**：SQLite WAL 模式提升并发读、Chroma 向量索引优化、定期备份 SQLite 数据文件。
